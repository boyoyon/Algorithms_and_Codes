(タスク) 連結成分ラベリング

何ものか？

こんな画像を

二値化すると

こんな感じになり、数を数えるのは簡単そうに思えるが、コンピューターには二値のデータの集まりにしか見えない。

画像処理において「繋がっている画素のグループ（連結成分）を見つけ、それぞれに固有の番号（ラベル）を割り当てるタスク」を連結成分ラベリング (CCL: Connected Componet Labeling) という。

「繋がっている」＝「近傍のピクセルとピクセル値が同じ (または差分が閾値以内)である」

ピクセルの近傍としては、4 近傍と 8 近傍があるので、どちらかを選択する。
(オレンジ色のピクセルに対して、水色のピクセルを近傍ピクセルとする)

手法

連結成分ラベリングの手法としては以下のような系譜がある。

マルチパス法

  • 2パス法
    [1] 『Sequential operations in digital picture processing』(1966)
    連結成分ラベリングの原点。1回目のスキャンで暫定ラベルを割り当てて同値類テーブルに記録し、2回目のスキャンで正しいラベルに置き換える「2パスアルゴリズム」の基礎を築いた。

輪郭追跡法

ピクセルの同値処理（Union-Findなど）を嫌い、オブジェクトの境界線を直接トレースすることで、1回の走査（あるいは最小限のアクセス）でラベリングと特徴抽出を同時に行う系統

  • Suzuki-Abeアルゴリズム
    [2] 『Topological structural analysis of digitized binary images by border following』(1985)
    日本の鈴木智正氏らによる有名な論文（OpenCVの findContours のベース）。輪郭追跡を行うことで、同値類テーブル（Union-Find）を使わずに、物体の外郭と穴の内郭を同時にラベリング・階層構造化する手法を提示した。

  • CTL: Contour Tracking Labeling
    [3] 『A linear-time component-labeling algorithm using contour tracing techniqu』(2004)
    輪郭追跡をさらに発展させ、画像全体を1回スキャンするだけでラベリングと特徴抽出（面積や重心など）を同時に完了させる「真の1パス」に近い効率化を達成した。

決定木とランラングス最適化

「隣接ピクセルの状態によって次に調べるべきピクセルは一意に決まる」という性質から不要なメモリアクセスを減らす決定木アプローチや、ピクセル単位ではなく連続する画素の塊（ラン）単位で処理する手法。

  • Fiorio法 (2パス Union-Find法)
    [4] 『Two linear time Union-Find strategies for image labeling』(1996)
    データ構造の「Union-Find（素集合データ構造）」をCCLの同値類解決に本格導入し、理論上および実用上の計算速度を大きく跳ね上げた。

  • SAUF：Smart Array-based Union-Find法
    [5] 『Optimizing connected component labeling algorithms』(2005)
    決定木（Decision Tree）を用いて、ラスタスキャン中に調べるべき近傍ピクセルの数を最小化（8連結なら4画素調べるのを平均1〜2画素に削減）する手法を提案。現代のCPUキャッシュ構造に適合し、高速化を実現した。

  • HCS: He, Chao, Suzuki 法
    [6] 『A fast connected-component labeling algorithm using a representative label table"』(2009)
    暫定ラベルを最小値に更新していく従来の無駄を省き、任意の暫定ラベルを代表値として即座にマージする手法（HCSアルゴリズムなど）を提案し、同値類解決のオーバーヘッドをさらに減らした。

並列・GPU最適化

  • BBDT: Block-based Decision Tree法
    [7] 『Parallel graph component labelling with GPUs and CUDA"』(2010)
    GPUの大量のスレッドを用いて、各ピクセルから局所的にラベルを伝播させ、最終的に画像全体の同期をとる並列CCLの初期の重要論文。

  • APL: Active Pixels Labeling法
    [8] 『A new active-pixels approach to connected-component labelling on GPUs』(2018)
    GPUの構造上ボトルネックになりやすいメモリアクセスを減らすため、変化のあった「アクティブなピクセル」のみを効率的に追跡してマージするアルゴリズムを提案した。

連結成分ラベリングのサーベイ論文
『The connected-component labeling problem: A review of state-of-the-art algorithms』(2017)

アルゴリズム概要

2パス法

(準備)
・検出する連結成分の最大数を決め、同値テーブルを作成する。
　(同値テーブルとは何か？は、おいおいわかってくる)
・ラベル 1 ～ 最大ラベル番号を、ラベル番号と同じ値で同値テーブルを初期化する。

(1パス目)
・画面を左上から右下に処理を進めるとする (上→下, 左→右)。

・ピンクのピクセルを処理する時点では水色の①②③④のピクセルは処理済である。

・ピンクのピクセルの値が 0 の場合
　→ ラベルバッファの対応する位置に 0 を書く。

・ピンクのピクセルの値が 255 で
　①②③④のラベルバッファの値がすべて 0 の場合
　→ 同値テーブルから仮ラベルを取得し、ラベルバッファに書く。
　　(同値テーブルのポインタを 1 つ進める)

・ピンクのピクセルの値が 255 で
　①②③④のラベル値に 0 ではない値がある場合
　→ ①②③④のラベル値で 0 以外の一番小さいラベル値をピンクのピクセルに対応するラベルバッファに書く。
　　①②③④のラベル値で最小ではないラベル値に対応する同値テーブルを一番小さいラベル値に更新する。

(2パス目)
・同値テーブルの内容に従って、ラベルバッファのラベルを振り直す。

お試しコード

OpenCV で Suzuki-Abe アルゴリズムをベースにしたラベリングの動作を確認できる。
(data/task_connected_componet_labeling/src/test_labeling.py) 



import cv2, sys
import numpy as np

# 二値化の閾値
TH = 64

argv = sys.argv
argc = len(argv)

print('%s executes connected component lableing' % argv[0])
print('[usage] python %s ' % argv[0])

if argc < 2:
    quit()

# 画像をグレースケールで読み込み、二値化する
gray = cv2.imread(argv[1], cv2.IMREAD_GRAYSCALE)
binImg = np.zeros(gray.shape, gray.dtype)

binImg[gray > TH] = 255
binImg[gray <= TH] = 0

nlabels, labels, stats, centroid = cv2.connectedComponentsWithStats(binImg)

・ nlabels：　ラベル数。背景のラベル(0)も含むため、連結成分数＋1 になる。
・ labels：　ラベルバッファ
・ stats：　外接矩形の left, top, width, height, 面積(ピクセル数)
・ centroid:　重心座標

ラベル番号が同じピクセルに同じ色をつけると、こんな感じになる。

連結成分のサイズも分かるので、サイズでフィルターを掛けることもできる。
